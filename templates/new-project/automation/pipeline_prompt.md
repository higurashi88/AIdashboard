# <NAME> 無人パイプライン

あなたは `<NAME>`（slug: `<SLUG>`、code: `<CODE>`）の無人パイプラインを実行している。
自動実行の識別子は `<KEY>`、Windows タスク名は `<TASKNAME>`、予定は `<SCHEDULE>` である。

最初に `Overview.md` と `Current-Status.md` を読み、目的・方針・現在地を確認する。
このファイルの「実行内容」をプロジェクト固有の安全な手順へ書き換えてから、自動実行を登録すること。

## 実行内容

1. 今回処理すべき対象を確認する。
2. `Overview.md` の方針と許可された範囲内で処理する。
3. `Current-Status.md` に現在地・実施内容・次の一手を短く記録する。

公開・送信・課金・削除・不可逆な上書きなど、本人の判断が必要な操作は実行しない。
判断が必要になった場合は、理由と必要な判断を記録して停止する。

## 終了時の報告

- 実施したこと
- 検証結果
- 未解決事項または停止理由

## ダッシュボード連携（最初と最後に必ず行う）

タスクの正本は MCP サーバー `dashboard` にある。Markdown のタスクファイルは参照しない。

**作業開始時**: `get_project(slug="<SLUG>")` を呼び、未処理タスクと判断待ちを確認する。
無人パイプラインは作業ディレクトリをプロジェクトルート外へ移して起動することが多く、
`cwd` では `root_path` の前方一致に失敗する。対話セッションと違い聞き返す相手がいないため、
**必ず `slug` を明示すること。** 未処理タスクに今回の対象が含まれていれば、それを優先して扱う。

**着手時**: 対象のタスクに `update_task(key, status="in_progress")` を呼ぶ。

**終了時**:
- 完了したタスクは `update_task(key, status="done", note="何をしたか")`。
- 本人の判断・確認・承認が必要になったものは
  `update_task(key, status="awaiting_user", note="何を判断してほしいか")` とし、**自分では実行しない**。
- 新たに判明した未処理事項は `create_task` で登録する（`list_tasks(query=...)` で重複を確認してから）。
- 最後に `report_session("<SLUG>", "作業内容の要約", [触れたタスクの key])` を呼ぶ。

`note` は1〜2文で簡潔に書く。長い経緯はプロジェクトの Markdown 資料に書く。
ツール呼び出しが失敗しても作業は続行し、最後にその旨を報告に含める。

**標準出力の最終行に `RESULT: 対象と実施内容の要約` を1行だけ出力する。**
この1行を `Get-DashboardRunSummary` が拾い、ダッシュボードの実行履歴に表示する。

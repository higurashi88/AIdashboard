# Discord 通知の導入手順

ダッシュボードの変化を Discord のチャンネルへ投稿する bot を、ゼロから用意して動かすまでの手順です。
所要時間は15分ほど。ダッシュボード本体の初回セットアップ（[docs/setup.md](setup.md)）が済んでいる前提です。

---

## 0. 何が届くか

| いつ | 内容 |
|------|------|
| タスクが「本人待ち」になったとき（1分以内） | タスクキー、タイトル、PJ名、判断してほしいことのメモ |
| 自動実行が失敗で終わったとき（1分以内） | 自動実行名、終了時刻、終了コード、要約、ログのパス |
| 毎朝（既定 8:00） | 判断待ちの一覧、人間が対応するタスク、PJ別の件数、直近24時間の自動実行の成否 |

種類ごとのオン・オフと、通知するプロジェクトの絞り込みは、あとから設定画面で変えられます。

**ダッシュボードをインターネットに公開する必要はありません。** bot は PC から Discord へ外向きに接続し、
ダッシュボードの API へは PC の中（Docker の内部ネットワーク）で読みに行きます。
bot はチャンネルへの投稿だけを行い、Discord 上のメッセージを読んだりコマンドを受け付けたりはしません。

---

## 1. 通知を受け取るサーバーとチャンネルを用意する

bot を招待するには、**自分が管理者のサーバー**が必要です。

1. Discord アプリの左端の「＋」（サーバーを追加）→「オリジナルの作成」→「自分と友達のため」で、自分専用のサーバーを作る
   （既に自分のサーバーがあれば、それを使って構いません）
2. 通知を流すテキストチャンネルを作る（例: `#dashboard`）。既定の `#一般` でも構いません

> チャンネルを「プライベートチャンネル」にする場合は、手順 3 の招待のあとで、そのチャンネルに bot を追加する必要があります（手順 3-3）。

---

## 2. Discord Developer Portal で bot を作る

ブラウザで <https://discord.com/developers/applications> を開き、Discord のアカウントでログインします。

### 2-1. アプリケーションを作る

1. 右上の **New Application** を押す
2. 名前を入れる（例: `AIdashboard`）。この名前がそのまま bot の表示名になります
3. 利用規約に同意して **Create**
4. **General Information** の **Application ID** をコピーして控える（手順 3 の招待 URL で使います）

### 2-2. bot の設定をする

左のメニューの **Bot** を開きます。

1. **Reset Token** を押し、表示された**トークン**をコピーして控える
   - **トークンは bot のパスワードです。** 他人に見せたり、チャットやリポジトリに貼ったりしないでください
   - 表示されるのはこのときだけです。分からなくなったら、もう一度 Reset Token を押して発行し直します（古いトークンは使えなくなります）
2. **Public Bot** を**オフ**にする（自分以外が、この bot を自分のサーバーへ招待できないようにする）
   - 「Private application cannot have a default authorization link」と出て保存できない場合は、
     左のメニューの **Installation** → **Install Link** を **None** にして保存してから、もう一度オフにする
3. **Privileged Gateway Intents**（Presence Intent / Server Members Intent / Message Content Intent）は**すべてオフのまま**にする
   - この bot はメッセージを読まないので、どれも不要です
4. 変更したら下に出る **Save Changes** を押す

---

## 3. bot をサーバーに招待する

### 3-1. 招待 URL を開く

次の URL の `<Application ID>` を手順 2-1 で控えた値に置き換えて、ブラウザで開きます。

```
https://discord.com/oauth2/authorize?client_id=<Application ID>&scope=bot&permissions=3072
```

`permissions=3072` は「チャンネルを見る（View Channels）」と「メッセージを送信（Send Messages）」の2つだけです。
bot に管理者権限などは渡しません。

> Developer Portal の **OAuth2 → URL Generator** で、SCOPES に `bot`、BOT PERMISSIONS に
> `View Channels` と `Send Messages` を選んでも、同じ URL が作れます。

### 3-2. 招待する

1. 「サーバーに追加」で手順 1 のサーバーを選ぶ
2. 権限が「チャンネルを見る」「メッセージを送信」の2つになっていることを確認して **認証**
3. サーバーのメンバー一覧に bot が（オフラインの状態で）表示されれば成功

### 3-3. プライベートチャンネルの場合だけ

通知先がプライベートチャンネルなら、bot が見えるようにします。

1. チャンネル名の横の歯車（チャンネルの編集）→ **権限**
2. **メンバーまたはロールを追加** で bot を追加し、「チャンネルを見る」と「メッセージを送信」を許可する

---

## 4. チャンネル ID と自分のユーザー ID を控える

Discord の ID は、開発者モードをオンにするとコピーできるようになります。

1. Discord アプリの **ユーザー設定**（左下の歯車）→ **詳細設定** → **開発者モード** をオン
2. 通知先のチャンネルを右クリック（スマホは長押し）→ **チャンネルIDをコピー**
   - 18〜20桁ほどの数字です（例 `123456789012345678`）。`#dashboard` のような名前ではありません
3. （任意）自分のアイコンを右クリック → **ユーザーIDをコピー**
   - 判断待ちと失敗の通知で自分をメンションしたいときに使います。メンションされるとスマホに確実に通知が届きます

---

## 5. ダッシュボード側で bot を起動する

### 5-1. bot 用の API キーを発行する

ダッシュボードの画面（<http://127.0.0.1:8770>）→ **設定 → APIキー** で、

- 名前: `discord-bot` など
- 用途: **Discord bot**

を選んで **発行** します。表示されたキー（`pdb_` で始まる文字列）を控えます。表示はこのときだけです。

> これは Discord のトークンとは別物です。bot がダッシュボードの API を読むためのキーです。

### 5-2. `.env` に2行足す

リポジトリ直下の `.env` をメモ帳などで開き、末尾に次の2行を足して保存します。

```dotenv
COMPOSE_PROFILES=discord
DASHBOARD_DISCORD_API_KEY=<5-1 で発行したキー>
```

`COMPOSE_PROFILES=discord` を書くと、以後 `docker compose up` で bot も一緒に起動するようになります。

### 5-3. bot を起動する

PowerShell でリポジトリ直下に移動して実行します。

```powershell
docker compose -f compose.yaml up -d --build discord-bot
```

この時点では、まだ Discord のトークンを入れていないので、bot は「設定待ち」で待機します。

---

## 6. 設定画面でトークンとチャンネルを入れる

ダッシュボードの **設定 → Discord bot** を開きます。

1. **Bot トークン**: 手順 2-2 で控えたトークンを貼る
2. **通知チャンネル ID**: 手順 4 の数字
3. （任意）**メンションするユーザー ID**: 手順 4 の自分のユーザー ID
4. （任意）**朝のまとめの時刻**、**確認間隔**
5. **保存**

15秒ほどで bot が設定を読み直して Discord に接続し、「bot の状態」が **接続済み** になります。
Discord のメンバー一覧でも bot がオンラインになります。

保存したトークンは画面に表示されません（末尾4文字だけ）。あとで変えたいときは「入れ直す」を押します。
**設定を変えても bot の再起動は要りません。**

### 6-1. テスト送信

同じ画面の **テスト送信** を押すと、通知チャンネルに「✅ テスト通知」が届きます。
届けば導入は完了です。画面に「送信しました」と出たのに届かない場合は、チャンネル ID が別のチャンネルを指していないか確認してください。

### 6-2. 通知の種類と対象を選ぶ

**設定 → 通知の種類と対象** で、判断待ち・自動実行の失敗・朝のまとめを個別にオン・オフできます。
プロジェクトにチェックを入れると、そのプロジェクトだけを通知します（1つも選ばなければ全プロジェクト）。

---

## 7. スマホで通知を受け取る

Discord のスマホアプリで同じアカウントにログインしておけば、プッシュ通知で届きます。

- **メンションを設定した場合**（手順 4-3）: 判断待ちと失敗は、通知設定を変えなくても届きます
- **メンションしない場合**: サーバーの通知設定が「@mentions のみ」だと鳴りません。
  テスト送信で鳴らなければ、サーバー名 → **通知設定** を「すべてのメッセージ」にするか、
  通知先チャンネルだけ「すべてのメッセージ」にします
- 朝のまとめはメンションしません。毎朝鳴らしたい場合は、上と同じく「すべてのメッセージ」にします

---

## 8. うまくいかないとき

まず **設定 → Discord bot** の「bot の状態」を見ます。

| 状態 | 原因と対処 |
|------|-----------|
| **bot から報告なし** / **bot から応答なし** | bot のコンテナが動いていない。`.env` の2行（手順 5-2）を確認し、`docker compose -f compose.yaml up -d --build discord-bot` を実行。ログは `docker compose -f compose.yaml logs --tail 50 discord-bot` |
| **設定待ち** | トークンかチャンネル ID が未入力。詳細に足りない項目が出る |
| **トークンが無効** | トークンが間違っているか、Developer Portal で Reset Token した後の古い値。手順 2-2 で発行し直して入れ直す |
| **チャンネルに投稿できない**（`Missing Access`） | bot がそのチャンネルを見られない。招待し忘れ（手順 3）か、プライベートチャンネルへの追加忘れ（手順 3-3） |
| **チャンネルに投稿できない**（`Unknown Channel`） | チャンネル ID の誤り。サーバー ID やメッセージ ID をコピーしていないか確認（手順 4-2） |
| 状態は接続済みだが、テスト送信で `Missing Permissions` | チャンネルは見えるが「メッセージを送信」が拒否されている。チャンネルの編集 → 権限で bot に許可する |
| 接続済みなのに通知が来ない | 「通知の種類と対象」でオフになっていないか、対象のプロジェクトが絞られていないかを確認。通知は「その時点から後」の変化だけで、過去の分はさかのぼって送らない |
| ログに `401 Unauthorized` が出る | `.env` の `DASHBOARD_DISCORD_API_KEY` が間違っているか、そのキーを画面で無効化した。手順 5-1 からやり直し、`up -d discord-bot` で作り直す |

---

## 9. トークンが漏れたかもしれないとき

1. Developer Portal → 対象のアプリ → **Bot** → **Reset Token** で発行し直す（古いトークンはその時点で使えなくなる）
2. ダッシュボードの **設定 → Discord bot** で新しいトークンを入れ直す

トークンはダッシュボードの DB に保存されるため、毎日のバックアップファイル（`backups/`）にも含まれます。
バックアップファイルを人に渡したり、公開の場所に置いたりしないでください。

---

## 10. 通知をやめる

- 一時的に止める: **設定 → 通知の種類と対象** ですべてオフにする（bot は接続したまま）
- bot ごと止める: `.env` の `COMPOSE_PROFILES=discord` を消し、`docker compose -f compose.yaml stop discord-bot`
- 完全にやめる: 上に加えて、Developer Portal でアプリを削除し、**設定 → APIキー** で bot 用のキーを無効化する
